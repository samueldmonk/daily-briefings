Top Story

Google patches a Chrome zero-day that attackers are already using

CVE-2026-85046 is a type-confusion flaw in V8, the JavaScript and WebAssembly engine behind Chrome, rated 8.8 on CVSS. Exploited successfully, it lets a remote attacker run arbitrary code inside Chrome’s sandbox after the victim simply visits a crafted HTML page. Technically, a V8 compiler bug causes an array holding PACKED_ELEMENTS to receive the PACKED_SMI_ELEMENTS map — which can be turned into arbitrary read/write on the JavaScript heap.

Google has confirmed an exploit exists in the wild but is withholding details of the threat actors, targets and campaigns while the update rolls out. Security Affairs counts this as the sixth actively exploited Chrome zero-day of 2026.

The fix ships as Chrome 152.0.7977.82/.83 for Windows and macOS and 152.0.7977.82 for Linux, distributed progressively. The bug was reported by researcher Salvatore Gulizia (Serotav) on August 4, 2026, for a $1,000 bounty.

⚠ Patch Priority — do this first today

Force the Chrome update to 152.0.7977.82/.83 and restart the browser on every managed endpoint rather than waiting for the automatic cycle. CVE-2026-85046 is the only item on this page that is both confirmed by the vendor as exploited in the wild and reachable by nothing more than a user visiting a web page.

Federal agencies have a harder deadline tomorrow. Of the seven vulnerabilities CISA added to the KEV catalog on September 2, 2026, CVE-2026-9586 (Sangoma Switchvox SQL injection) carries a remediation due date of September 5, 2026. Remediation windows are assigned per-CVE under CISA’s risk-based directive, so treat each due date individually rather than assuming a fixed window.

Threat Actor Spotlight

NewEspionageChina-linked

Fire Ant moves from hypervisors to the network itself

Sygnia has documented Fire Ant, a China-linked cyber-espionage actor, expanding beyond VMware hypervisors to compromise Cisco IOS XR routers, TACACS servers and Linux management hosts in high-value networks. The investigation began with a GRE tunnel on an IOS XR router that had no configuration or history to justify it.

The implants were purpose-built for the IOS XR control plane: they replaced a system library so that only log messages containing the string “Health” were forwarded, and altered the command execution path by appending an | exclude filter to show commands — hiding the tunnel from administrators looking straight at it.

On the TACACS server the group deployed TacTap, injecting a malicious library into the tac_plus process and dumping credentials to /var/log/.tacplus.acct under a one-byte XOR — a technique Sygnia says had not been publicly described before. Elsewhere the actor combined Medusa and REPTILE rootkits, custom SSH backdoors, and binaries impersonating SentinelOne and Cybereason agents, while suppressing SNMP traps, disabling SELinux and rewriting access logs.

Breaches & Incidents

NewReport

AI agents ran a full ransomware intrusion in under 10 hours

Unit 42 detailed an incident in which a human attacker used edge AI models and agent frameworks to compromise a network almost autonomously. Per the attacker’s own statement during negotiations, the agents executed more than 50 MITRE ATT&CK techniques — mapping internal architecture, pulling tokens and passwords from code repositories, escalating to master credentials for the secret manager, hijacking CI/CD pipelines to exfiltrate cloud keys, and attempting to plant backdoors. The attacker then used the victim’s own compromised cloud AI infrastructure as post-compromise infrastructure.

NewVendor patch

ServiceNow patches three CVSS 10.0 flaws in its AI Platform

CVE-2026-18885 (code injection in the GraphQL Composite Data API, unauthenticated arbitrary code execution), CVE-2026-18886 (inadequate access control in the configuration image upload processor, privilege escalation) and CVE-2026-74820 (SQL injection in a dynamic schema ORDER BY clause) are each rated CVSS v4.0 10.0 by ServiceNow. Hosted instances are already patched; self-managed deployments must apply it manually. ServiceNow states it is not aware of active exploitation.

NewMalware

PackClient: a commercial RAT sold on Telegram, used by TA4922

Proofpoint identified PackClient, a modular remote-access framework with dual C2 channels, a keylogger, screenshot capture, SOCKS tunnels and specific monitoring of apps such as Telegram Desktop. Chinese actor TA4922 has used it against organisations in China and India via tax-themed lures and ZIP/IMG files that install the malware through DLL sideloading. Its commercial availability raises the odds of wider adoption.

Browser

A second Chrome update, distinct from the zero-day

Separately from the actively exploited V8 bug, Google’s stable-channel release fixed 26 flaws including two the vendor rates critical: CVE-2026-84353 (Shared Tab Groups) and CVE-2026-84352 (WebGL), both use-after-free issues at CVSS v3 9.6 that allow sandbox escape from a malicious page. That build is 152.0.7977.75/.76. The zero-day fix is the later 152.0.7977.82/.83 — do not mistake one for the other.

CISA KEV & Federal Deadlines

  • Seven vulnerabilities were added to the KEV catalog on September 2, 2026 (the date is anchored to CISA’s own alert URL path /2026/09/02/): CVE-2026-9586 (Sangoma Switchvox, SQL injection), CVE-2026-48710 (Kludex Starlette, HTTP request/response smuggling), CVE-2026-49869 (Kestra OSS, OS command injection), CVE-2026-59822 (BerriAI LiteLLM, improper authentication), CVE-2026-82329 (JFrog Artifactory, improper authentication), CVE-2026-83548 and CVE-2026-83549 (SonicWall SMA1000).
  • CVE-2026-9586 — due September 5, 2026 (1 day left). The nearest federal deadline on the board. Sangoma Switchvox operators inside civilian agencies are out of runway after tomorrow.
  • CVE-2026-48710 — due September 16, 2026 (12 days left). The longer window on the same batch, which is exactly why the deadlines have to be read per-CVE.
  • Remediation windows are risk-based and assigned per vulnerability. The old flat three-week heuristic no longer holds; the two dates above come from the same September 2 batch and are eleven days apart. Always take the due date CISA publishes for the specific CVE.
Due dates for the remaining five of the seven were not individually confirmed this run and are therefore not asserted here.
