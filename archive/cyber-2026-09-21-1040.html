Top Story

A pre-auth RCE in Orkes Conductor is being exploited in the wild — and the fix has been out since June

CVE-2026-58138 carries a CVSS v3.1 score of 9.8 and a CVSS v4 score of 9.3. Per NVD, “Orkes Conductor 3.21.21 before 3.30.2 contains an unauthenticated remote code execution vulnerability that allows remote attackers to execute arbitrary OS commands by submitting inline workflow definitions containing malicious JavaScript or Python expressions to the workflow API endpoint prior to authentication.” The attack path runs through unsandboxed GraalVM evaluators configured with HostAccess.ALL or allowAllAccess(true), reachable via the INLINE, LAMBDA, DO_WHILE and SWITCH task types, and commands execute with the privileges of the Conductor process.

Fortinet issued an outbreak alert this week after observing attackers submitting crafted workflow definitions to the Conductor workflow API. As of 9 September the company had blocked 1,290 attempts in 24 hours, a 132% increase in daily activity, and nearly 7,000 attempts between 2 and 9 September. Most of the activity originated from Germany, Hong Kong, Indonesia, the U.A.E. and India. Previdian reports three exploitation attempts against its honeypots since 24 July from two IP addresses in France and the US; Empirical Security detected in-the-wild exploitation as recently as 21 August.

The patch landed in Conductor 3.30.2 in June; proof-of-concept code was published in early August and exploitation began shortly after. Where patching is not immediate, Fortinet advises restricting external access to Conductor workflow API endpoints, placing instances behind network access controls, and monitoring for unexpected command execution.

This replaces the SparroWocky / FamousSparrow top story carried in the previous edition, which was not re-verified this run. Under this desk’s fact-check rule, the story verified at source today takes the slot.

Patch Priority

Patch the Linux kernel kTLS receive path today — CVE-2025-39682, due 21 September, 0 days left

CVE-2025-39682 (CVSS 9.8) is an improper check for unusual or exceptional conditions in the Linux kernel’s TLS receive path (net/tls/tls_sw.c): a zero-length record retrieved from the rx_list bypasses intended recvmsg() record-type handling, which can be driven to memory disclosure or denial of service. CISA added it to the KEV catalog on 18 September with federal remediation required by 21 September under BOD 26-04 — that is today, 0 days left — alongside CVE-2026-53266 and CVE-2025-39964. All three are additionally flagged as requiring forensic triage: agencies must investigate potentially exposed assets for evidence of compromise, not merely install the patch.

One headline read this run described the order as due “by Sunday” (20 September); every other account read this run — including the write-ups that list all three CVE identifiers — states 21 September. This page uses 21 September and names the outlier rather than averaging them. The two overdue Cisco deadlines are in the KEV section below and are not restated here.

Threat Actor Spotlight

NewExtortion

The PEC impersonator — an attacker who logged in as the Italian state

The actor behind the Revolut disclosure did not break Revolut. They claim to have held access to Italian law enforcement email accounts for six months, obtained via infostealer malware, and used PEC — Italy’s government-overseen certified email system for official and legal correspondence — to send what looked like legitimate agency data requests. Revolut confirmed it disclosed sensitive customer information after fraudulent requests appeared to come from a legitimate agency email, and the exchanges continued for months. The attacker is now demanding $3 million in Monero and has separately claimed a 147 GB haul from the Italian police systems. The tradecraft is the point: no exploit against the target, only a trusted channel wearing the right return address.

Breaches & Incidents

NewFintech

Revolut hands over ~700 customers’ data to fake government requests

Revolut confirmed a customer data breach carried out through fraudulent requests that appeared to come from a legitimate Italian agency address on the PEC network. Reports put the exposure at nearly 700 customers, including birth dates, postal and email addresses, phone numbers and copies of identity documents such as passports and driver’s licences, along with transaction details. One account frames the targets as high-value crypto accounts and puts the figure at 680; both counts are printed rather than reconciled.

NewMalware

Rapuncel abuses a Microsoft-attested driver to switch off 145 security tools

A newly identified information-stealing campaign tracked as Rapuncel loads a Microsoft-attested Windows kernel driver to gain kernel-level control and shut down 145 antivirus and endpoint security processes before stealing browser and wallet credentials. The technique — Bring Your Own Vulnerable Driver — has become the preferred method for attackers who need to neutralise security software before deploying ransomware or infostealers.

NewMalware

Remus goes after AI assistant credentials, not just browsers

Remus, which surfaced on underground marketplaces in March 2026, removes syscall hooks to evade EDR and has expanded beyond browser passwords and crypto wallets. SpyCloud Labs found recent builds harvesting password-manager and 2FA-extension artifacts, application credentials and AI assistant credential folders — including access tokens, MCP configurations, prompt histories and project data. Named targets include Claude, Cursor and OpenCode, and OpenAI and Anthropic API tokens.

NewRansomware

Ransomware crews turn on a VMware vCenter flaw patched in July

CISA has warned that ransomware gangs have begun exploiting CVE-2026-59310, a critical directory traversal vulnerability in the vCenter Syslog server that unauthenticated attackers can use to execute arbitrary code. The fix shipped in July. No CVSS figure was stated in the sources read this run, so none is printed.

CarriedPublic sector

Florida DMV archive: 612,982 files, and it is not a headcount

Carried from the standing record and not restated at source this run: the leaked FLHSMV archive runs to roughly 52.3 GB across six folders and 612,982 ZIP files (416,042 in the first folder alone) — a file count, explicitly not a count of people. FLHSMV learned of it on 4 September and traced it to one Plant City Police Department user’s credentials improperly housed on a personal device.
