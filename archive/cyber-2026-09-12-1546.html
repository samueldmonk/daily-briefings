Top Story

A maximum-severity Magento flaw was being exploited three days before Adobe had a patch — and its federal deadline passed yesterday, eleven days earlier than this page had been reporting

CVE-2026-75650, which Sansec named StyleSmuggler, is an unauthenticated arbitrary-code-execution flaw in Adobe Commerce, Adobe Commerce B2B and Magento Open Source. Adobe rates it Critical at CVSS 10.0, classifies it Priority 1, and states it is being exploited in the wild. The weakness is an improper neutralization of special elements in a template engine (CWE-1336): attacker-controlled data reaches Magento's template system through styles properties and is executed during server-side rendering, on a path that can be triggered through the Payment Transaction Failed Reminder email. Code execution happens while the server renders the content — nobody has to open the email.

The timeline is the reason this leads. Sansec observed the first confirmed exploitation on 4 September, published its analysis on 5 September after reproducing the unauthenticated chain on clean Magento Open Source 2.4.7, 2.4.8 and 2.4.9 installs, and watched implant variants appear on the 6th and the 7th. Adobe's emergency bulletin APSB26-146 and the VULN-39341 hotfix did not arrive until 7 September. Sansec's first identified victim was running 2.4.6-p15 with the July and August 2026 security updates already installed — patched to the month, and still exploitable. A second, separate actor used the same flaw to drop a PHP web shell below Magento's media cache.

There is a trap in the remediation that is worth stating plainly. Adobe published its regular September Commerce update, APSB26-138, on 8 September, and its installation guidance says explicitly that installations receiving APSB26-138 must also receive the VULN-39341 hotfix. A 2026-sep build does not contain the fix. Adobe also instructs operators to rotate the Commerce encryption key, admin passwords, REST/SOAP/GraphQL integration tokens, OAuth secrets, payment-gateway credentials, database credentials and privileged service accounts — and notes that rotating the encryption key does not invalidate credentials an attacker has already taken; each secret has to be rotated at the system that issued it.

And this page had the deadline wrong. CISA added CVE-2026-75650 to the KEV catalog on 8 September with a remediation due date of 11 September — a three-day window. Previous editions listed it in a four-CVE group all due 22 September, which put it eleven days late and, worse, made it look like a routine fourteen-day item rather than an emergency one. This site's own standing corrections file already recorded that "the 8 September batch of four split between 11 and 22 September"; the page never applied the split. The entry is corrected below, the countdown now reads overdue, and the failure was one of carrying a batch as a single row instead of taking the date CISA states per CVE — which is the rule this page publishes in its KEV section below.

Second Read — AI Infrastructure as a KEV Category

AI infrastructure has become a KEV category of its own — and the exploitation behind it is credential theft and cryptomining, not research

A CISA batch of seven newly exploited flaws, read in full this run, lands squarely on the tooling organisations have bolted onto their AI stacks. Two of the seven are in AI-specific software: CVE-2026-49869 (CVSS 10.0), an OS command injection in Kestra OSS that lets an unauthenticated remote attacker create and execute arbitrary workflows without credentials, and CVE-2026-59822 (CVSS 8.8), an improper-authentication flaw in Berri LiteLLM's Model Context Protocol Streamable HTTP endpoint that lets an unauthenticated attacker open an authenticated MCP session with an arbitrary bearer token. A third, CVE-2026-48710 (CVSS 6.5), is an HTTP request/response smuggling flaw in Kludex Starlette — a general-purpose ASGI framework, not an AI product — which enters this story because it chains into the LiteLLM attack path described below.

The other four are conventional perimeter and supply-chain targets: CVE-2026-83548 (CVSS 10.0, SSRF) and CVE-2026-83549 (CVSS 7.8, post-authentication OS command injection) in SonicWall SMA 1000 appliances, which SonicWall says it investigated a case indicating active exploitation of; CVE-2026-9586 (CVSS 9.3), an SQL injection in Sangoma Switchvox reachable by a single crafted request from an unauthenticated attacker; and CVE-2026-82329 (CVSS 9.8), an improper-authentication flaw in JFrog Artifactory that, under default configuration, hands administrative privileges to an unauthenticated attacker with network access.

What the attackers did with them is the part worth dwelling on. Reporting from Horizon3.ai and watchTowr has the Switchvox and Artifactory flaws weaponised to deploy reverse shells and mint admin tokens for follow-on enumeration of users, groups, credential sets and federated access topologies. A Microsoft report has Kestra likely exploited in late June 2026 to establish a reverse shell, perform Docker container discovery and defence evasion, deploy a cryptocurrency miner and facilitate data harvesting — Microsoft describes four impact paths, including host resource hijacking through miner deployment and container-environment exposure through Docker socket access. On LiteLLM, attackers chained CVE-2026-42271 (CVSS 8.7) with CVE-2026-48710 to reach remote code execution, delivered an XMRig miner via an ELF binary after fingerprinting the host and terminating competing miners, then reached the LiteLLM-backed PostgreSQL tier to harvest model configuration, upstream provider key material and proxy-issued virtual keys, with persistence added through ~/.ssh/authorized_keys.

Microsoft and Wiz both name the broader target set — LiteLLM, Flowise, LangChain, Langflow, ChromaDB, Ollama, Marimo and MCP servers — and Microsoft's own guidance is the line to take away: defenders should monitor AI workloads according to their control-plane role, not only as isolated applications. A separate suspected campaign is exploiting exposed RAGFlow instances to steal LLM provider keys. Two things this page does not claim: that every one of these intrusions had a ransomware payload, and that the objectives were uniform beyond what Microsoft states — credential collection, durable access and resource monetisation.

Patch Priority

Most urgent action today — deadline is today

CVE-2026-20079 — Cisco Secure Firewall Management Center (FMC) Software, CVSS 10.0. An unauthenticated remote attacker can bypass authentication and execute script files to obtain root. It is in the KEV catalog as actively exploited and the federal remediation deadline is Saturday 12 September 2026 — today, —. If an FMC instance is reachable and unpatched, it is the single thing to fix before anything else on this page. Cisco has since updated its own advisory to say it became aware of active exploitation in August 2026, and that it identified three clusters of post-compromise activity on FMC instances — tracked as UAT-12197, UAT-11823 and UAT-11988 — deploying web shells and malware.

The same 9 September alert carried two more flaws on the same deadline, and both now have exploitation figures attached. CVE-2026-19490 (Citrix NetScaler ADC and NetScaler Gateway, CVSS 9.3, authentication bypass when the appliance is configured as an AAA virtual server or as a Gateway) has drawn 56 attempts against Previdian's honeypots since 3 September, 36 of them on 8 September alone. CVE-2025-25249 (Fortinet FortiOS, FortiSwitchManager and FortiSASE, CVSS 7.3, heap-based buffer overflow reachable by an unauthenticated attacker) is the flaw SOCRadar ties to a campaign delivering a Node.js remote access trojan called PivotC2: more than 3,000 IP addresses targeted and 178 devices infected, concentrated in the United States, assessed to a financially motivated Russian-speaking actor, with the earliest evidence of exploitation dating to July 2026.

Threat Actor Spotlight

NewTwo actors

The StyleSmuggler operators — an implant crew, and someone else entirely

Sansec's reporting describes two separate actors working the same Adobe Commerce flaw, which is the detail that makes this more than one campaign. The first deploys implants that hide behind ordinary-looking process and path names — [kworker/u:8:0], fc-cache, chronyd, and files under ~/.local/share/.gvfsd/, ~/.cache/fontconfig/ and randomly suffixed directories in /tmp — with variants appearing on 6 and 7 September as the campaign matured. The second simply drops a PHP web shell beneath Magento's media cache; unexpected executable PHP under pub/media is the check for it. Neither is named, and no ransomware brand is attached to either in anything read this run. Sansec also published network indicators for correlation, including hosts that typosquat legitimate services — time.microsft.run, ntp.timesysnc.net, windwsecurity.run.

CarriedRansomware

Qilin (also tracked as Agenda) — tied to the AI-gateway exploitation chain

Wiz links threat actors associated with Qilin, also known as Agenda, to active exploitation of the CVE-2026-42271 plus CVE-2026-48710 LiteLLM chain — the same chain Microsoft traced to XMRig deployment and provider-key theft. Wiz says it has separately observed exploitation attempts involving CVE-2026-59822 against its honeypots, probing model enumeration endpoints. The significance is not the brand: it is that a ransomware-affiliated crew is working an AI gateway as an entry point, alongside the VPNs and edge appliances that fill the rest of this page. This page does not assert that Qilin deployed ransomware in these specific intrusions — what the sources establish is exploitation of the chain and monetisation through mining.

CarriedAgentic

The PaperCut campaign — hundreds of AI agents, 48 countries

A likely Russian-speaking actor used hundreds of AI agents — an OpenAI Codex harness plus a DeepSeek model, with targets drawn from Netlas — to exploit CVE-2026-81578 and CVE-2026-82078 in PaperCut NG/MF. At least 440 instances, 395 organisations, 48 countries; credentials from 280 victims, OS and domain secrets from 147, admin at 12. Empty workspace to first RCE in under four hours; 11 organisations in 26 seconds once the campaign launched; one US high school from initial access to domain admin in seven minutes. No ransomware brand and no objective are claimed — GreyNoise could not determine one.

CISA KEV & Federal Deadlines

  • Added 9 September, due 12 September — Cisco CVE-2026-20079, Citrix CVE-2026-19490 and a Fortinet flaw. — A three-day window. This is the deadline the Patch Priority box above names, and the two boxes use the same date by construction.
  • Added 10 September, due 13 September — MikroTik CVE-2026-67277 and CVE-2026-86060. — Another three-day window; CISA flagged CVE-2026-86060 as requiring forensic triage.
  • Added 11 September, due 14 September — GitLab CVE-2026-85706 (CVSS 10.0). — Three days again, on an unauthenticated maximum-severity flaw.
  • Added 2 September, due 16 September — Kludex Starlette CVE-2026-48710 and Berri LiteLLM CVE-2026-59822. — These two were carved out of their own batch for a longer window; the other five in that batch were due 5 September and are therefore past deadline.
  • Added 4 September, due 18 September. — Fourteen days.
  • Added 8 September, due 11 September — Adobe Commerce CVE-2026-75650 (CVSS 10.0). — Three days, and the correction this edition makes: earlier editions of this page put this CVE in the fourteen-day group below. It was never in it.
  • Added 8 September, due 22 September — CVE-2026-85880, CVE-2026-81963, CVE-2026-86218. — Fourteen days, including the two Windows zero-days fixed in the 8 September Patch Tuesday. The same four-CVE bulletin therefore carries both a three-day and a fourteen-day clock.
  • Added 9 September, due 23 September — Chromium V8 CVE-2026-87491. — Fourteen days, from the same alert as the three-day group above. Fixed in Chrome 153.0.8010.36.
  • How to read these windows. BOD 22-01 is revoked. CISA issued BOD 26-04, "Prioritizing Security Updates Based on Risk," on 10 June 2026, replacing the uniform three-week clock with a 16-tier matrix keyed to public exposure, KEV membership and whether exploitation can be fully automated. The most dangerous tier is three days with mandatory forensic triage; agencies must be operating to these timelines by 7 December 2026. Do not derive a KEV deadline — take the date CISA states per CVE. Across six add dates this site has now logged both three-day and fourteen-day windows, and twice — the 8 September and 9 September alerts — both intervals appeared within a single alert. The second of those two was only visible to this page once the Adobe row above was corrected.
  • A pattern, offered as observation and not as a rule. Three-day windows have so far attached to perimeter network and security appliances and to unauthenticated maximum-severity flaws; fourteen-day windows to browser and local-privilege bugs. GitLab fits the first group. That is six add dates of description, not a published CISA policy. Note also that KEV entry requires evidence of exploitation, so a severe flaw with no confirmed exploitation carries no federal deadline at all — which is exactly the status of the two CVSS 9.8 Check Point VPN flaws in the table above.
