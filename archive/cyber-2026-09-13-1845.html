Top Story

New this edition

A CVSS 10.0 in GitLab lets a stranger read your secrets out of the repository server — and the probes started within hours

CVE-2026-85706 carries the maximum CVSS score, 10.0, and the reason is the absence of anything standing in the way. It is a path-traversal flaw in GitLab’s repository commits API that, per GitLab’s own wording, stems from “improper path confinement and missing authentication enforcement” — an unauthenticated attacker can read arbitrary files off the server. The only precondition watchTowr names is that at least one public project must exist on the instance. Affected: GitLab Community and Enterprise Edition, all versions from 18.7 before 19.1.8, 19.2 before 19.2.6 and 19.3 before 19.3.2. Patches shipped 10 September in 19.1.8, 19.2.6 and 19.3.2.

What makes this a file-read worth leading with is what the files contain. watchTowr says the flaw is being used to pull log files and GitLab configuration files — the places credentials, CI/CD secrets and tokens live. Its head of threat intelligence, Jake Knott, notes that access to a GitLab instance means source code, build pipelines and everything downstream of them, and warns that the move to indiscriminate mass exploitation is “likely not far away.” In-the-wild probing was observed from 06:00 UTC on 11 September 2026, hours after disclosure. CISA added the CVE to the KEV catalog the same day and set a federal remediation date of 14 September 2026. A second critical shipped in the same releases: CVE-2026-87719 (CVSS 9.9), an insecure-deserialization bug in GitLab EE reachable by an authenticated user with Duo Chat access. Detection tip from watchTowr, printed because it is actionable: review logs for HTTP POST requests to /api/v4/projects/{id}/repository/commits/ carrying a file.Path parameter. This is GitLab’s second critical in recent weeks, after the CVE-2026-19478 GraphQL code-injection flaw that was also exploited almost immediately.

Still running — carried and re-confirmed

“MikroTrick” comes due today. The two MikroTik RouterOS flaws CISA added on 10 September compose into unauthenticated device takeover: CVE-2026-67277 (CVSS 8.8), missing authentication in the btest service, leaking kernel memory and drivable to denial of service; and CVE-2026-86060 (CVSS 9.2), which rewrites the trusted RouterOS policy mask to escalate privilege. CERT Polska named the chain and reported unidentified actors using it against routers reachable over SSH; a headline read this run — “Attackers Hijack MikroTik Routers Through Internet-Exposed SSH Without Authentication” — restates the same finding independently. Federal remediation date 13 September 2026, today, with CVE-2026-86060 additionally flagged for forensic triage under BOD 26-04. One caveat unresolved: a vulnerability tracker scores CVE-2026-86060 at 9.8; the CISA-derived 9.2 is what this page prints.

BlueMoon. The exploit kit Proofpoint documented earlier this week chains CVE-2026-85046 (type confusion in Chrome’s V8 engine) → CVE-2026-87491 (V8 sandbox escape) → CVE-2026-85880 (heap-based buffer overflow in Windows ALPC) to get from a clicked link to SYSTEM on a fully updated machine. The China-linked TA412 / APT31 was first seen using it on 28 August 2026; within days UNK_LateNight, UNK_DoubleCheck and UNK_QuietRacket were running the identical chain. Carried from the previous edition; nothing read this run changed it.

Patch Priority

Deadline tomorrow — 1 day left

GitLab CE/EE — CVE-2026-85706 (CVSS 10.0). Added to the KEV catalog 11 September 2026, federal remediation date 14 September 2026. Upgrade self-managed instances to 19.1.8, 19.2.6 or 19.3.2, or remove public internet exposure if the instance does not need it. The same releases fix CVE-2026-87719 (CVSS 9.9), so this is one upgrade for both. It takes priority over yesterday’s entry because it is maximum severity, needs no authentication, is already being probed in the wild, and — unlike the RouterOS pair, whose 13 September deadline expires today and which remains fully live in the KEV section below — it is a deadline that can still be met. Both dates are stated per CVE exactly as they appear in the KEV section; neither is derived.

Threat Actor Spotlight

Newunattributededge devices

The MikroTrick operators — identity unknown, access total

CERT Polska attributes the RouterOS exploitation only to unknown threat actors, and that vagueness is the point: the chain needs no credentials, no user interaction and no foothold — just an SSH-reachable router. Edge network gear sits outside most EDR coverage and logs sparsely, so the population of compromised devices is likely larger than the population of detected ones. Contrast with TA412/APT31 and the BlueMoon clusters above, which are named, tracked and phishing-dependent: those you can teach users to resist; this one you can only patch.

Breaches & Incidents

Newmobile malware

Mantax Otax — Android ransomware that also spies on you, and then harasses you

Zimperium’s zLabs team has documented an Android strain that refuses to pick a category. Mantax Otax encrypts files with AES — skipping system-critical directories — appends a .enc extension, locks the screen, and pushes the victim into an on-device chat portal with the operators to arrange payment. While it does that it is also stealing lock-screen PINs, SMS messages, one-time passwords, browser history, contacts, call logs, the installed-app list, Google account details and location, capturing images from both cameras, watching WhatsApp and Telegram activity, and recording the screen through Android’s MediaProjection API. Distribution is outside Google Play: malicious APKs pushed to Indonesian users through phishing and social engineering. One design note worth the attention of defenders: it fetches its command-and-control domain from GitHub at runtime, so the operators can rotate infrastructure without shipping new code. OTP theft plus file encryption in one package is double extortion and account takeover from the same foothold.

extortion

INC Ransom claims a 5.7-terabyte haul

The INC Ransom group claimed responsibility for an intrusion in September and alleges it exfiltrated 5.7 terabytes of data. Printed as a claim, with the volume attributed to the group itself: nothing read this run carries a victim confirmation or an independent verification of the figure, and extortion crews routinely overstate. Re-confirmed this run from a September round-up; still no victim named. Included because the number, if anywhere near right, is unusually large for a single victim.

supply chain

Trezor — 347,000 addresses phished through its email vendor

Newsletter provider Brevo was breached on 9 September, an incident touching 120 Brevo accounts. The attacker sent mail that genuinely originated from Trezor’s own campaigns, subject-lined “Critical Security Alert: STM32 Entropy Vulnerability”, steering readers to a site built to harvest wallet seeds. 347,000 addresses were targeted, 2,500 clicked, and Trezor killed the domain within 20 minutes. Only the newsletter database was exposed; no Trezor system was compromised. Re-confirmed this run.

Windows administrators continue to report that the September 2026 security updates cause Remote Desktop Services failures on Windows Server 2019, 2022 and 2025 — re-confirmed this run, and framed as it was before: an availability defect, no CVE and no attacker. Worth stating plainly during a week when the same patch cycle is also the remedy for two exploited zero-days: the pressure to deploy fast and the risk of deploying fast are pointing in opposite directions.

How these deadlines are set — and why one of them is three days

BOD 22-01 is revoked. CISA replaced it on 10 June 2026 with BOD 26-04, “Prioritizing Security Updates Based on Risk”, which also revokes BOD 19-02. The old flat three-week KEV window is gone; in its place is a risk matrix keyed to four variables — whether the asset is publicly exposed, whether the CVE is in KEV, whether exploitation can be fully automated, and the technical impact achieved after exploitation. Deadlines are tiered at 3, 14 or 60 days. A vulnerability meeting all four high-risk criteria must be remediated in three calendar days — the most aggressive standing timeline in the history of federal cyber directives, and the reason the RouterOS pair added on 10 September came due on 13 September. Agencies must be operating to these timelines by 7 December 2026; the directive binds federal civilian agencies, not the private sector. Two consequences for reading this page: a same-week deadline is now normal and must not be “corrected” to three weeks, and CVEs in the same bulletin can carry different dates — take the stated date per CVE, never derive it. A corollary worth keeping: KEV entry requires evidence of exploitation, so a severe flaw nobody is exploiting carries no federal deadline at all. Absence from KEV is not a severity judgement.
