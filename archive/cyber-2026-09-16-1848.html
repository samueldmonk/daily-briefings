Top Story

The Cisco ISE maximum-severity bypass now has a federal deadline: Saturday 19 September

CVE-2026-76460 is an authentication bypass in an API of Cisco Identity Services Engine, published today in advisory cisco-sa-ISE-ABP-VNSW7Tn5 with a base score of 10.0 — CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H, the maximum, with a changed scope — and classified CWE-648, incorrect use of a privileged API. The flaw is due to insufficient authentication control on an API endpoint: an unauthenticated remote attacker sends a crafted request directly to the exposed endpoint, bypassing the web-based management interface entirely, and executes commands with root privileges. The same access lets an attacker erase log entries to conceal what was done.

Two facts from the advisory carry the weight. First: “The Cisco PSIRT is aware of active exploitation of this vulnerability.” Second, under Source: “This vulnerability was found during the resolution of a Cisco Technical Assistance Center (TAC) support case.” Read together, they say the bug surfaced because a customer was already in trouble — at least one production environment was compromised before the flaw was known to exist. It affects Cisco ISE and ISE-PIC regardless of device configuration.

This edition supersedes three earlier ones today on the deadline question. Each of those stated — correctly, at the time it was written — that no federal remediation date could be confirmed, because CISA’s alert pages returned empty bodies on direct fetch. CISA added the CVE on 16 September in a two-CVE alert, catalogued as “Cisco Identity Services Engine Incorrect Use of Privileged APIs Vulnerability” alongside CVE-2026-87886 (Acronis Backup, incorrect default permissions leading to local privilege escalation), and the assigned due date is 19 September 2026 — a three-day window.

There is no workaround. Cisco’s only stated mitigation is infrastructure access control lists restricting who can reach the management plane at all. For remediation Cisco directs customers to Release 3.4 Patch 2 (no further action if already there) or Release 3.3 Patch 7 if running 3.3 Patch 6; the fixed builds across the branch are 3.1 Patch 12, 3.2 Patch 11, 3.3 Patch 12, 3.4 Patch 7 and 3.5 Patch 4. ISE 3.0 is End of Software Maintenance and receives no fix at all — on 3.0, the only remediation is migration. Because root access lets an attacker edit local evidence, corroborate any hunt with off-box network and firewall logs, and re-image nodes you cannot clear.

Patch Priority — today

Cisco Identity Services Engine and ISE-PIC — CVE-2026-76460, CVSS 10.0, actively exploited, no workaround. CISA KEV due date 19 September 2026 (3 days left). Move to 3.4 Patch 2, or 3.3 Patch 7 from 3.3 Patch 6; the full fixed set is 3.1 P12 / 3.2 P11 / 3.3 P12 / 3.4 P7 / 3.5 P4. ISE 3.0 gets no fix. If you cannot patch tonight, restrict management access with iACLs and start hunting: root access permits log tampering, so corroborate off-box before you clear a node. Second in the queue is CVE-2026-76461 in Cisco Secure Email Gateway, whose federal deadline is tomorrow, 17 September.

Gunra — an affiliate program with a fresh alias

Gunra launched a formal ransomware-as-a-service affiliate program in January 2026, handing affiliates access to management panels and ransomware builders. The FBI has observed the group adopting new branding aliases including “Golden Community”. CISA carries it under its #StopRansomware series as advisory AA26-222A. Disclosed 14 Sep · patched 10 Sep · Wordfence / StellarWP

Two unauthenticated RCE chains in The Events Calendar expose hundreds of thousands of WordPress sites

Wordfence disclosed CVE-2026-78006 and CVE-2026-78159, both CVSS 9.8, in The Events Calendar plugin. The first is an unauthenticated PHP object injection reachable through comments submitted on event pages: the guard in is_safe_widget_instance can be bypassed by supplying a forged wp_hash integrity attribute, which passes validation before unserialize() is called. The second is remote code execution in the parse_array logic, triggered by crafted widget data. StellarWP shipped 6.17.4.1 on 10 September to close the object-injection path; anything at or below 6.17.4 should be treated as affected. Outcomes range from administrator password resets to full server compromise. The exposure count is disputed: coverage read this run puts it at more than 600,000 sites, while SecurityWeek’s headline says 200,000+. Both are reported here; neither is averaged into a third number.

Active exploitation · Wordfence telemetry

WooCommerce Wholesale Lead Capture: 100,000+ blocked exploit attempts since June

CVE-2026-27540 (CVSS 9.8) is an arbitrary file upload caused by missing file-type validation in the wwlc_file_upload_handler AJAX action, affecting all versions of the premium Rymera Web Co plugin up to and including 2.0.3.1. Attackers submit crafted requests with a forged file_settings parameter and a malicious PHP file — observed as shell.php — giving unauthenticated remote code execution. Wordfence has blocked more than 100,000 attempts since June 2026, 99 of them in the past 24 hours, across roughly 6,000 active installations. It was patched on 20 February in 2.0.3.2.

16 Sep · Google / Mozilla

Chrome 153 and Firefox patch 115 flaws between them

Google shipped Chrome 153 (stable 153.0.8010.47/.48 on Windows and macOS, .47 on Linux) fixing 42 vulnerabilities, three of them Critical: CVE-2026-91726, an out-of-bounds read in WebGL; CVE-2026-91721, a use-after-free in Internals; and CVE-2026-91749, a use-after-free in Workers. A further 28 are rated High, including use-after-frees in Input, Skia, DOM, V8, PDF, Core, Auth, DigitalCredentials and WebAppInstalls, plus an integer overflow in V8. Mozilla fixed 73 bugs in Firefox the same day. Google did not state that any of the 42 are being exploited in the wild.

Active exploitation · watchTowr honeypots

WSO2 API Manager signature-verification flaw under attack

CVE-2026-5430 is improper verification of a cryptographic signature: a JWT is accepted when signed with an unsupported algorithm, letting an attacker forge administrator tokens and take over accounts. WSO2’s own advisory, published 3 May 2026, scores it 10 and notes it is adjusted to 9.8 in single-tenant deployments, where impact stays inside one security-authority boundary — which is why some coverage prints 9.8 in body text while quoting 10.0. What is new is the exploitation: watchTowr honeypots caught forged tokens on 13 September. Hacktron Team is credited with the discovery.
