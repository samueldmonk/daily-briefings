Top Story

Microsoft just shipped the largest security update in its history — 966 flaws, two of them Windows zero-days that attackers were already using to become SYSTEM

September's Patch Tuesday fixed 966 vulnerabilities. BleepingComputer, which counts only what Microsoft releases on Patch Tuesday itself, calls it Microsoft's largest security update ever, and the comparison is the point: 570 flaws in July, 400 in August. A further 204 flaws were fixed earlier in the month and are not in that total at all.

The shape of the release: 438 elevation of privilege, 258 remote code execution, 173 information disclosure, 56 denial of service, 19 security feature bypass and 16 spoofing. 105 are rated Critical, of which 81 are remote code execution, 20 elevation of privilege, 2 information disclosure and 1 a security feature bypass.

Two of the 966 were being exploited before a fix existed. This page has carried both CVE identifiers for several editions on the strength of their KEV entry alone; this is the first edition that can say what they are. CVE-2026-81963 is an elevation of privilege in the Windows Update Stack — in Microsoft's words, improper link resolution before file access ("link following") allowing an authorized attacker to elevate locally — and it yields SYSTEM. It is credited to Romain Deperne and the Microsoft Threat Intelligence Centre (MSTIC). CVE-2026-85880 is a heap-based buffer overflow in Windows Advanced Local Procedure Call (ALPC), likewise exploited to gain SYSTEM, discovered by Volexity and by Mark Kelly, David Galazin and Jeremy Hedges of Proofpoint. Microsoft has published no detail on how either was exploited. Both sit in the KEV catalog with a 22 September federal deadline — fourteen days, against the three-day clock on the appliance flaws below. The CVSS 7.8 in the table below for each is carried from an earlier edition, not re-sourced here, and the Patch Tuesday write-up gives no score for either. No source read attributes the difference between the two windows to a specific BOD 26-04 tier, so this page does not either.

The reason the number is a record is stated by the source, and it is worth sitting with. BleepingComputer attributes the increase in Patch Tuesday volume to Microsoft having begun using an AI-powered vulnerability discovery system to find more flaws across its products. That is a defensive use of the same class of tooling this page has spent several editions tracking on the offensive side — the PaperCut campaign run by hundreds of AI agents, the exploited AI gateways in the third read below. A record patch load is not, by itself, a record level of danger; it is a record level of finding. The operational consequence for anyone running Windows estates is nonetheless real, because 966 fixes have to be tested and shipped on the same calendar as before, and two of them were already being used against somebody.

The same bulletin round-up lists advisories from other vendors, several of which this page already tracks: Adobe's StyleSmuggler emergency fix (second read, below), SonicWall's two chained SMA1000 zero-days, MikroTik's two actively exploited RouterOS flaws, a Google Chrome V8 zero-day plus eleven other Chrome fixes, a maximum-severity "OVERPASS" flaw in the SAP Kernel, an emergency hotfix for a maximum-severity N-able N-central RCE, a critical RCE in HPE ArubaOS-CX, an unpatched ConnectWise ScreenConnect flaw with mitigations only, and a CrowdStrike advisory after an anonymous researcher released a zero-day against the agent.

Second Read — The Magento Zero-Day

The Magento flaw that was exploited three days before Adobe had a patch is a week old now, and its federal deadline has been overdue since yesterday

CVE-2026-75650, which Sansec named StyleSmuggler, is an unauthenticated arbitrary-code-execution flaw in Adobe Commerce, Adobe Commerce B2B and Magento Open Source. Adobe rates it Critical at CVSS 10.0, classifies it Priority 1, and states it is being exploited in the wild. The weakness is an improper neutralization of special elements in a template engine (CWE-1336): attacker-controlled data reaches Magento's template system through styles properties and is executed during server-side rendering, on a path that can be triggered through the Payment Transaction Failed Reminder email. Code execution happens while the server renders the content — nobody has to open the email.

The timeline is the reason this ran as the top story for two editions. Sansec observed the first confirmed exploitation on 4 September, published its analysis on 5 September after reproducing the unauthenticated chain on clean Magento Open Source 2.4.7, 2.4.8 and 2.4.9 installs, and watched implant variants appear on the 6th and the 7th. Adobe's emergency bulletin APSB26-146 and the VULN-39341 hotfix did not arrive until 7 September. Sansec's first identified victim was running 2.4.6-p15 with the July and August 2026 security updates already installed — patched to the month, and still exploitable. A second, separate actor used the same flaw to drop a PHP web shell below Magento's media cache.

There is a trap in the remediation that is worth stating plainly. Adobe published its regular September Commerce update, APSB26-138, on 8 September, and its installation guidance says explicitly that installations receiving APSB26-138 must also receive the VULN-39341 hotfix. A 2026-sep build does not contain the fix. Adobe also instructs operators to rotate the Commerce encryption key, admin passwords, REST/SOAP/GraphQL integration tokens, OAuth secrets, payment-gateway credentials, database credentials and privileged service accounts — and notes that rotating the encryption key does not invalidate credentials an attacker has already taken; each secret has to be rotated at the system that issued it.

The correction this page made last edition, carried forward. CISA added CVE-2026-75650 to the KEV catalog on 8 September with a remediation due date of 11 September — a three-day window. Previous editions listed it in a four-CVE group all due 22 September, which put it eleven days late and, worse, made it look like a routine fourteen-day item rather than an emergency one. This site's own standing corrections file already recorded that "the 8 September batch of four split between 11 and 22 September"; the page never applied the split. The entry is corrected below, the countdown now reads overdue, and the failure was one of carrying a batch as a single row instead of taking the date CISA states per CVE — which is the rule this page publishes in its KEV section below.

Third Read — AI Infrastructure as a KEV Category

AI infrastructure has become a KEV category of its own — and the exploitation behind it is credential theft and cryptomining, not research

A CISA batch of seven newly exploited flaws, read in full in an earlier edition and carried unchanged, lands squarely on the tooling organisations have bolted onto their AI stacks. Two of the seven are in AI-specific software: CVE-2026-49869 (CVSS 10.0), an OS command injection in Kestra OSS that lets an unauthenticated remote attacker create and execute arbitrary workflows without credentials, and CVE-2026-59822 (CVSS 8.8), an improper-authentication flaw in Berri LiteLLM's Model Context Protocol Streamable HTTP endpoint that lets an unauthenticated attacker open an authenticated MCP session with an arbitrary bearer token. A third, CVE-2026-48710 (CVSS 6.5), is an HTTP request/response smuggling flaw in Kludex Starlette — a general-purpose ASGI framework, not an AI product — which enters this story because it chains into the LiteLLM attack path described below.

The other four are conventional perimeter and supply-chain targets: CVE-2026-83548 (CVSS 10.0, SSRF) and CVE-2026-83549 (CVSS 7.8, post-authentication OS command injection) in SonicWall SMA 1000 appliances, which SonicWall says it investigated a case indicating active exploitation of; CVE-2026-9586 (CVSS 9.3), an SQL injection in Sangoma Switchvox reachable by a single crafted request from an unauthenticated attacker; and CVE-2026-82329 (CVSS 9.8), an improper-authentication flaw in JFrog Artifactory that, under default configuration, hands administrative privileges to an unauthenticated attacker with network access.

What the attackers did with them is the part worth dwelling on. Reporting from Horizon3.ai and watchTowr has the Switchvox and Artifactory flaws weaponised to deploy reverse shells and mint admin tokens for follow-on enumeration of users, groups, credential sets and federated access topologies. A Microsoft report has Kestra likely exploited in late June 2026 to establish a reverse shell, perform Docker container discovery and defence evasion, deploy a cryptocurrency miner and facilitate data harvesting — Microsoft describes four impact paths, including host resource hijacking through miner deployment and container-environment exposure through Docker socket access. On LiteLLM, attackers chained CVE-2026-42271 (CVSS 8.7) with CVE-2026-48710 to reach remote code execution, delivered an XMRig miner via an ELF binary after fingerprinting the host and terminating competing miners, then reached the LiteLLM-backed PostgreSQL tier to harvest model configuration, upstream provider key material and proxy-issued virtual keys, with persistence added through ~/.ssh/authorized_keys.

Microsoft and Wiz both name the broader target set — LiteLLM, Flowise, LangChain, Langflow, ChromaDB, Ollama, Marimo and MCP servers — and Microsoft's own guidance is the line to take away: defenders should monitor AI workloads according to their control-plane role, not only as isolated applications. A separate suspected campaign is exploiting exposed RAGFlow instances to steal LLM provider keys. Two things this page does not claim: that every one of these intrusions had a ransomware payload, and that the objectives were uniform beyond what Microsoft states — credential collection, durable access and resource monetisation.

Patch Priority

Most urgent action today — deadline is today

CVE-2026-20079 — Cisco Secure Firewall Management Center (FMC) Software, CVSS 10.0. An unauthenticated remote attacker can bypass authentication and execute script files to obtain root. It is in the KEV catalog as actively exploited and the federal remediation deadline is Saturday 12 September 2026 — today, —. If an FMC instance is reachable and unpatched, it is the single thing to fix before anything else on this page. And when tonight’s clock runs out, the next one is already running: the two MikroTik RouterOS flaws fall due tomorrow, 13 September, and one of them — CVE-2026-86060, now sourced at CVSS 9.2 — carries a mandatory forensic-triage obligation on top of the patch. Cisco has since updated its own advisory to say it became aware of active exploitation in August 2026, and that it identified three clusters of post-compromise activity on FMC instances — tracked as UAT-12197, UAT-11823 and UAT-11988 — deploying web shells and malware. Two further details were returned by search in an earlier edition and are attributed rather than asserted: Help Net Security's headline pairs CVE-2026-20079 with a second FMC flaw, CVE-2026-20316, and a search result summarising reporting on the Talos research says one of the three clusters deployed a web shell to deliver malicious JAR files while another is linked to the Russian-based APT known as Sandworm.

The third cluster has a name now. A search return in the previous edition gives the Talos finding as Sandworm, Qilin and a credential-theft cluster all exploiting CVE-2026-20079 — which fills in the label this page has been carrying as "financially motivated groups". The Sandworm arm is identified as UAT-11823, tied to GRU Unit 74455, deploying the ELF implant Cyclops Blink. Naming a ransomware brand alongside a state espionage group on the same appliance is the operational point: the same unpatched box serves both an intelligence objective and an extortion one, and only one of those announces itself. CISA's add date for the flaw is re-confirmed this run as 9 September.

The Sandworm attribution got more specific this run, and so did the mechanism and the timeline. A second search return, independent of the first, gives the Talos finding as three distinct threat-actor clusters on the FMC management plane comprising financially motivated groups and the Russian Sandworm / GRU group, the latter deploying Cyclops Blink malware. The flaw itself is now described at a level this page could not state before: the root cause is an improperly created system process at boot time, classified CWE-288, and it is reached by sending crafted HTTP requests to an affected device. And the clock is longer than the page has been saying: Cisco PSIRT confirmed exploitation in August 2026, but indicators of compromise place activity as early as 23 July 2026. That does not contradict the August date — it means the confirmed window opened weeks after the observed one, which is the ordinary shape of these disclosures and the reason a deadline being met today does not mean an estate was clean in July. All of it is search-level: neither the SecurityWeek nor the Talos page has been fetched at source in any edition, and cisa.gov's own alert pages again returned empty when fetched, being JavaScript-gated, so the federal dates below rest on secondary reporting and on the CISA alert titles themselves.

What to actually install — newly sourced in an earlier edition, and carried unchanged here. Stated at all because "patch it" is not an instruction. Neither the Cisco branch list nor the Citrix builds were returned again this run; both are carried. What this run did add is the GitLab side, in the KEV section below: fixed builds 19.3.2 / 19.2.6 / 19.1.8, shipped 10 September. For Cisco FMC, hot fixes exist for release branches 7.0, 7.2, 7.4, 7.6, 7.7 and 10.0, and there is no workaround that fully addresses the flaw — restricting management-interface access to trusted administrative networks reduces exposure but does not substitute for the fix. For Citrix NetScaler, customer-managed appliances go to 14.1-73.32 or later, 13.1-63.21 or later, 14.1-73.32 FIPS or later, or 13.1-37.277 or later on the 13.1-FIPS/NDcPP train. Both sets of builds come from reporting of the vendors' own bulletins rather than from a roundup's restatement.

The same 9 September alert carried two more flaws on the same deadline, and both now have exploitation figures attached. CVE-2026-19490 (Citrix NetScaler ADC and NetScaler Gateway, CVSS 9.3, authentication bypass when the appliance is configured as an AAA virtual server or as a Gateway) has drawn 56 attempts against Previdian's honeypots since 3 September, 36 of them on 8 September alone. CVE-2025-25249 (Fortinet FortiOS, FortiSwitchManager and FortiSASE, CVSS 7.3, heap-based buffer overflow reachable by an unauthenticated attacker) is the flaw SOCRadar ties to a campaign delivering a Node.js remote access trojan called PivotC2: more than 3,000 IP addresses targeted and 178 devices infected, concentrated in the United States, assessed to a financially motivated Russian-speaking actor, with the earliest evidence of exploitation dating to July 2026.

Threat Actor Spotlight

Two actors

The StyleSmuggler operators — an implant crew, and someone else entirely

Sansec's reporting describes two separate actors working the same Adobe Commerce flaw, which is the detail that makes this more than one campaign. The first deploys implants that hide behind ordinary-looking process and path names — [kworker/u:8:0], fc-cache, chronyd, and files under ~/.local/share/.gvfsd/, ~/.cache/fontconfig/ and randomly suffixed directories in /tmp — with variants appearing on 6 and 7 September as the campaign matured. The second simply drops a PHP web shell beneath Magento's media cache; unexpected executable PHP under pub/media is the check for it. Neither is named, and no ransomware brand is attached to either in anything read. Sansec also published network indicators for correlation, including hosts that typosquat legitimate services — time.microsft.run, ntp.timesysnc.net, windwsecurity.run.

CarriedRansomware

Qilin (also tracked as Agenda) — tied to the AI-gateway exploitation chain

Wiz links threat actors associated with Qilin, also known as Agenda, to active exploitation of the CVE-2026-42271 plus CVE-2026-48710 LiteLLM chain — the same chain Microsoft traced to XMRig deployment and provider-key theft. Wiz says it has separately observed exploitation attempts involving CVE-2026-59822 against its honeypots, probing model enumeration endpoints. The significance is not the brand: it is that a ransomware-affiliated crew is working an AI gateway as an entry point, alongside the VPNs and edge appliances that fill the rest of this page. This page does not assert that Qilin deployed ransomware in these specific intrusions — what the sources establish is exploitation of the chain and monetisation through mining.

CarriedAgentic

The PaperCut campaign — hundreds of AI agents, 48 countries

A likely Russian-speaking actor used hundreds of AI agents — an OpenAI Codex harness plus a DeepSeek model, with targets drawn from Netlas — to exploit CVE-2026-81578 and CVE-2026-82078 in PaperCut NG/MF. At least 440 instances, 395 organisations, 48 countries; credentials from 280 victims, OS and domain secrets from 147, admin at 12. Empty workspace to first RCE in under four hours; 11 organisations in 26 seconds once the campaign launched; one US high school from initial access to domain admin in seven minutes. No ransomware brand and no objective are claimed — GreyNoise could not determine one.

Breaches & Incidents

NewPatch fallout

September's Windows Server updates are breaking Remote Desktop, and rolling them back gives up the security fixes

Microsoft's September 2026 cumulative updates are causing Remote Desktop Services failures on Windows Server 2019, 2022 and 2025 — KB5122876, KB5122882 and KB5122871 respectively, all released 8 September. The failure pattern is the awkward part: affected servers run normally for a few hours after installation, then Remote Desktop connections start failing, existing sessions cannot disconnect or log off, and new attempts hang before timing out. Reports surfaced first on Reddit's r/sysadmin, where administrators in unrelated environments described the same behaviour independently — which is what separates a systemic bug from a local misconfiguration. Microsoft told BleepingComputer it is aware and investigating, with guidance to follow. Administrators who removed the updates report Remote Desktop returns, but that also removes this month's security fixes, so the workaround trades one exposure for another. This is an availability defect, not a vulnerability: no CVE, no attacker, nothing to exploit.

Government

Florida confirms its DMV database was breached using a police employee's credentials

The Florida Department of Highway Safety and Motor Vehicles has confirmed a breach of its DAVID driver database, saying the attackers got in using credentials belonging to an employee of a police department. The mechanism is the story: the state database was not broken into directly, it was entered through a legitimate downstream account that was authorised to query it. No record count appears in what was read, so none is published.

153 million

IDScan confirms a breach behind a database of 153 million driver's-license scans

The identity-verification company IDScan has confirmed that attackers accessed customer data held in its cloud platform — days after reports tied the company to a database holding more than 153 million driver's licence scans. The confirmation and the 153 million figure are two claims: the company confirms the access, and the figure is the reported size of the database the reports linked to it.

Supply chain

Trezor: 347,000 customers targeted with phishing after a breach at Brevo

The hardware-wallet maker says phishing against its customers earlier in the week reached 347,000 email addresses and that 2,500 users clicked the embedded malicious link. The headline ties the campaign to a breach at Brevo. How the addresses were obtained, and what Brevo is to Trezor, are not stated in what was read, so this page does not describe either. Clicks are not the same as losses, and no loss figure is stated.

Artifactory flaws chained in the wild to plant a Rust backdoor

Attackers are chaining critical and high-severity flaws in JFrog Artifactory to bypass authentication, take administrative privileges and deploy a Rust backdoor on vulnerable self-hosted servers. This attaches live intrusion activity to CVE-2026-82329 (CVSS 9.8), which has been in the table below as a KEV entry since the 2 September batch.

  • How to read these windows. BOD 22-01 is revoked. CISA issued BOD 26-04, "Prioritizing Security Updates Based on Risk," on 10 June 2026, replacing the uniform three-week clock with a 16-tier matrix keyed to public exposure, KEV membership and whether exploitation can be fully automated. The most dangerous tier is three days with mandatory forensic triage; agencies must be operating to these timelines by 7 December 2026. Do not derive a KEV deadline — take the date CISA states per CVE. Across six add dates this site has now logged both three-day and fourteen-day windows, and twice — the 8 September and 9 September alerts — both intervals appeared within a single alert. The second of those two was only visible to this page once the Adobe row above was corrected.
  • A pattern, offered as observation and not as a rule. Three-day windows have so far attached to perimeter network and security appliances and to unauthenticated maximum-severity flaws; fourteen-day windows to browser and local-privilege bugs. GitLab fits the first group. That is six add dates of description, not a published CISA policy. Note also that KEV entry requires evidence of exploitation, so a severe flaw with no confirmed exploitation carries no federal deadline at all — which is exactly the status of the two CVSS 9.8 Check Point VPN flaws in the table above.
