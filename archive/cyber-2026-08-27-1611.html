The federal deadline to patch a maximum-severity Oracle WebLogic proxy flaw has now expired

New at 4:05 — the clock has run out. The remediation date for CVE-2026-21962 was today, August 27. As of this edition it is past, and the countdown below reads overdue rather than 0 days left. No source fetched this run reported a compliance figure, an extension, or any enforcement action, and none is invented. What changes on this page is the label on the clock, nothing more — but an unpatched maximum-severity flaw does not become less urgent for having missed its date, so the item stays at the top.

CISA added CVE-2026-21962 to its Known Exploited Vulnerabilities catalog on August 24, confirming that attackers are using the flaw against Oracle HTTP Server and the Oracle WebLogic Server Proxy Plug-in, and instructed federal agencies to remediate it by August 27 — today.

Oracle rates the vulnerability CVSS 10.0. The attack arrives over HTTP with no authentication, no user interaction and no existing privileges, and lets an attacker access or modify critical data through crafted HTTP requests. The vulnerable components are the WebLogic Server Proxy Plug-in for Apache HTTP Server and for Microsoft IIS, including deployments bundled with Oracle HTTP Server.

New at 12:38 — who is using it, and how hard. CVE-2026-21962 is among several vulnerabilities a China-linked threat actor has exploited against government and commercial infrastructure across more than 100 countries to deliver the SNOWLIGHT downloader; SOCRadar reported in July that the flaw was already in that actor's toolkit against government targets. Separately, a CloudSEK honeypot study recorded more than 140,000 attack attempts from 21 countries over a 12-day window. Both figures come from reporting fetched this run and are attributed rather than merged; no link is asserted between the honeypot traffic and the named actor, because no source seen makes one.

A fix has existed since January 20, 2026, when Oracle disclosed and patched the issue in its January Critical Patch Update — roughly seven months before CISA flagged exploitation.

New this run — a second deadline is now confirmed behind it. For four editions this page reported the August 26 KEV batch with no due date, because none had been verified. One now has been: CISA has ordered federal agencies to remediate CVE-2026-8452 in Citrix NetScaler ADC and NetScaler Gateway by Saturday, August 29. Citrix patched the flaw on June 30, 2026, and initially assessed it as denial-of-service only; researchers at watchTowr subsequently demonstrated that successful exploitation can yield remote code execution as root on unpatched appliances, and it is now being exploited in the wild to plant web shells — observed intrusions drop files named x.php and z.php and run discovery commands such as id and echo. Fixed builds are 14.1-72.61 (FIPS), 13.1-63.18 and 13.1-37.272. Updated at 12:05 — the score is no longer blank: SecurityWeek reports that Citrix itself assigned the flaw a CVSS of 8.8 when it reported the issue at the end of June, so the "not confirmed" cell this page carried for four editions is now filled with a vendor figure rather than a blog's. The three-day window is consistent with the per-CVE, risk-based dates BOD 26-04 replaced the old fixed three-week rule with.

Carried · 2:41ArrestsSupply chain

Two charged in Australia over TeamPCP — the poisoned-scanner campaign that turned two security tools into a credential harvester

New at 2:41: the Australian Federal Police has charged two Western Australian men with a combined 14 offences over their alleged role in TeamPCP, the group behind the March 2026 compromise of the open-source security scanners Trivy and Checkmarx KICS and the AI gateway LiteLLM. Louis Michael Gaebler, 23, and Ruben Ian Thomson, 21, appeared in Perth Magistrates Court on August 27, a day after the AFP and the Western Australia Police Force executed search warrants at properties in Cottesloe, Hamilton Hill and Mandurah and seized devices for forensic analysis. Police allege the two were “principal participants” in the syndicate and were paid in cryptocurrency of a value still under investigation.

The chain is the reason this matters to defenders. Credentials taken in the Trivy compromise were turned on the Checkmarx KICS actions days later; LiteLLM’s own build pipeline installed Trivy without pinning it to a verified version, the poisoned scanner took the project’s publishing token, and that token was used to push backdoored LiteLLM releases in late March. The AFP puts the blast radius at more than 1,000 organisations potentially compromised, more than 500,000 credentials stolen and at least 300 GB of data exfiltrated. The practical control is the one the chain defeated: pin build-time security tooling to a verified version and treat scanners as part of the supply chain, not as neutral observers of it. Charges are allegations and no conviction is asserted here.

Critical vulnerabilityBackup & monitoringCarried

Veeam patches a CVSS 10.0 unauthenticated RCE in Veeam ONE

Veeam has fixed a set of vulnerabilities in Veeam ONE, its monitoring and reporting platform. The most severe, CVE-2026-64633, carries a CVSS v4.0 score of 10.0 — the maximum — because it allows remote, unauthenticated code execution on the Veeam ONE agent host. Affected builds are Veeam ONE 13.0.2.6723 and all earlier version 13 releases; the fix is Veeam ONE 13.1.0.7034, described in Veeam knowledge-base article KB4892. Separately, CVE-2026-65641, CVSS v4.0 9.3, lets a remote unauthenticated attacker force the Veeam ONE service to initiate an SMB authentication attempt — a classic credential-relay primitive; Veeam disclosed it in KB4905, published August 25, 2026, and credited a report via HackerOne. The wider update set also addresses flaws allowing sensitive-file access, database data theft and privilege escalation. No source seen this run reports exploitation in the wild, and neither CVE appears in the KEV additions verified this run, so no federal deadline is stated. (Cybersecurity News, GBHackers, Veeam KB4892 / KB4905)

The Aurora affiliate story is now quantified: 20+ victims, nine countries, and an exposed server showing the whole workflow

The single-affiliate case first carried here in one line is now documented in detail. A Russian-speaking affiliate of the Aurora ransomware operation compromised more than 20 organisations across nine countries between April and July 2026, using the AI coding assistant Cursor to plan intrusion activity and Active Directory escalation. One naming caveat is worth stating. The reporting fetched this run names Cursor as the assistant in the logs, and that is what is printed.
