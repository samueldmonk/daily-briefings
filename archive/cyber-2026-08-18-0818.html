Top Story

CISA flags an actively exploited Ray flaw that turns a visited web page into remote code execution

The US Cybersecurity and Infrastructure Security Agency on Monday added a critical flaw in Ray to its Known Exploited Vulnerabilities catalog, citing evidence of active exploitation. Ray is the open-source, Python-native distributed computing framework used to scale AI and machine-learning workloads; its GitHub project has more than 43,500 stars and has been forked over 7,900 times.

The vulnerability is CVE-2025-62593, CVSS 9.4, and it can result in remote code execution through the victim's web browser — specifically Firefox and Safari — by means of a DNS rebinding attack. The root cause is a design decision rather than a coding slip. As Ray's own maintainers put it in their November 2025 advisory: "Due to the longstanding decision by the Ray Development team to not implement any sort of authentication on critical endpoints, like the /api/jobs & /api/job_agent/jobs/ has once again led to a severe vulnerability that allows attackers to execute arbitrary code against Ray. This time in a development context via the browsers Firefox and Safari." The technical hinge is insufficient control against browser-based attacks in scenarios where the User-Agent header can be modified.

What that means in practice. The flaw primarily hits developers running Ray in development and testing environments. Combined with DNS rebinding, it is exploitable against a developer who merely visits a malicious website or is served a malicious advertisement — no phishing click on an attachment required, and no credentials involved. Worse, the maintainers note the attack can be extended to network-adjacent Ray instances, using the browser as a confused-deputy intermediary to reach Ray clusters running inside a private corporate network. The issue is fixed in Ray 2.52.0; versions before that insufficiently protected the dashboard and API. Oligo's Avi Lumelsky is credited with the fetch bypass and Jonathan Leitschuh with the DNS rebinding attack.

On the exploitation evidence. CISA has not shared any details of how the vulnerability is being exploited in the wild. What is on the record is a BitSight report from March 2026 finding that the operators of the RondoDox DDoS botnet had incorporated the vulnerability into their arsenal two days before it was publicly disclosed on November 26, 2025, helped by the availability of proof-of-concept exploit code. Separately, Oligo reports that unpatched Ray instances have been attacked in a campaign dubbed ShadowRay 2.0, which turns infected clusters with NVIDIA GPUs into a self-replicating cryptocurrency-mining botnet. Federal Civilian Executive Branch agencies have been told to apply fixes and mitigations by August 20, 2026.

This entry also settles an open question in this briefing. A KEV aggregator surfaced the Ray addition yesterday evening, but the add date could not be corroborated against a CISA alert page at the time and the deadline was deliberately withheld rather than published on a single unconfirmed source. CISA's own alert page for August 17 now confirms it, and the deadline is published here for the first time.

Patch Priority

Do this first — two days left CVE-2025-62593 — Ray, all versions before 2.52.0. CVSS 9.4, actively exploited, added to CISA KEV on August 17 with a federal remediation deadline of August 20, 2026. Upgrade the Python package to 2.52.0. If you cannot upgrade today, the exposure to worry about is a developer workstation with a Ray dashboard or API reachable on localhost or the local network while that developer browses the open web — so restrict access to the dashboard and API endpoints (/api/jobs and /api/job_agent/jobs/ in particular), and treat any internet-reachable Ray instance as already compromised until proven otherwise.
And these are already late Five KEV deadlines in the list below have already passed — PTC Windchill (June 28), JetBrains TeamCity (August 8), Progress LoadMaster (August 10), and both Metabase and Cisco ASA/FTD (August 14). The Metabase flaw in particular has a verified downstream victim list, so an unpatched instance is not a theoretical risk.

Threat Actor Spotlight

Ransomware

The Gentlemen

A ransomware operation that first appeared in August 2025 and has scaled faster than almost anything else in the ecosystem, expanding from 35 victims in the fourth quarter of 2025 to 182 in the first quarter of 2026. It remains active this month: KFC Kosova was posted as a victim on August 15, 2026, and Avanta Maroc, an HR and recruitment agency in Casablanca, has also been claimed.

The context around it matters as much as the group itself. Qilin is now the largest-volume operator in the current threat landscape, and Akira — first seen in 2023 — is among the longest-running ransomware-as-a-service operations still going. Across the twelve months from April 2025 to March 2026, 7,551 publicly disclosed ransomware victims were tracked, a 24.9% increase on the previous reporting period. Ransomware has not spiked; it has settled at an elevated new normal, which is a harder problem to plan around.

Separately this month, a suspected China-nexus advanced persistent threat has been attributed with exploiting a newly patched flaw in Broadcom VMware vCenter and deploying Babuk-derived ransomware.

Breaches & Incidents

BreachNew

SafePal — 39,798 crypto wallet customers

The hardware-wallet maker disclosed on August 16 that an authorisation flaw in the order-tracking function of a plug-in allowed unauthorised external access to customer order data. 39,798 customers are affected. Exposed: names, email addresses, shipping addresses, phone numbers and purchase details, for orders placed between March 2, 2025 and April 11, 2026. Not exposed: seed phrases, private keys, wallet passwords, bank account information, payment card numbers and government-issued ID numbers. SafePal says it has remediated the flaw, engaged a third-party security firm for an audit, cut data retention to 90 days and taken down over 30 phishing websites linked to the breach. The stolen information is reported to be advertised for sale. As with the Trezor–ShipMonk exposure disclosed on August 13, the danger is not the crypto — it is that the data set is a verified list of hardware-wallet owners with home delivery addresses.

BreachNew

Heights Finance — over 1.2 million individuals

Heights Finance Holdings Co. discovered on May 7, 2026 that an unauthorised actor had accessed a third-party cloud-based platform used to store certain customer data, and began notifying individuals on August 11. The incident affects more than 1.2 million people. Stolen data includes names, addresses, Social Security numbers and bank account details, and may also include phone numbers, email addresses, tax IDs, driver's licence and state ID numbers, and dates of birth. The company says the activity was limited to the cloud platform and did not affect its loan management systems or other networks; it has secured the platform, engaged cybersecurity specialists, reported the incident to federal law enforcement and is offering 24 months of credit monitoring and identity protection. Several law firms have opened investigations.

Zero-dayVictim chain

Metabase — five companies lost customer data before disclosure

CVE-2026-72898, CVSS 10.0, unauthenticated SQL injection via /api/session/reset_password, exploited before disclosure. Metabase disclosed on August 6, by which point five companies had already lost customer data. Framework notified all customers (names, emails, phone numbers, physical addresses; no payment data). Anaconda and n8n, both Metabase Cloud tenants, disclosed unauthorised customer-data access from the pre-patch window. Trezor disclosed on August 13 that its shipping provider ShipMonk was breached the same way: 13,689 Trezor customers — 11,742 with full exposure (name, email, phone, shipping address) and 1,947 partial — across orders delivered May 10 to August 8 in the US, UK, Sweden, Colombia, Brazil, Italy and Portugal. No private keys were touched and no device was compromised. CISA added the flaw to KEV on August 11.

Credential theft

Azure tenants — 3.6M+ employee records advertised

A seller is advertising more than 3.6 million employee records exfiltrated from nine corporate Microsoft Azure tenants, with claimed volumes of roughly 1.7 million at McDonald's, 800,000 at TCS, 425,000 at Vodafone, 250,000 at HCL, more than 185,000 at IHG, 170,000 at Kyndryl, 80,000 at Gap, 20,000 at Hexaware and 9,000 at Wyndham. The actor claims Global Administrator access in some tenants. Every figure is the seller's own claim; no company named has confirmed a breach, and the access is described as obtained with stolen valid credentials rather than through any flaw in Azure itself.

Also on the Wire

  • The Keyv npm worm. A credential-stealing worm that first appeared in keyv@6.0.0 spread beyond the Keyv and Cacheable namespaces into hundreds of packages across multiple organisations on August 4. SafeDep verified 353 poisoned versions across 79 package names in the npm registry. The malicious releases use a preinstall script to run a credential-stealing bundle inside developer and CI environments; SafeDep and Socket say it can harvest repository, package-registry, cloud and private-key material, then use whatever npm publishing access it finds to poison more packages.
  • cPanel and WHM servers under attack from GitHub-hosted runners. Attackers are abusing compromised GitHub repositories and hosted runners — 583 workflows across 10 versions — to scan for servers vulnerable to CVE-2026-41940, an authentication bypass. Once triggered by a repository push or manual run, the workflows launch a GitHub-hosted runner, download a Linux payload from attacker infrastructure and begin scanning.
  • Over 4.9 million Salesforce records containing some personally identifiable information have been reported compromised.
  • GeoServer, still unpatched. An unauthenticated SQL injection in the jsonArrayContains filter expression, which may reach RCE in certain H2-database deployments, was disclosed publicly on August 12 with no coordination; watchTowr saw exploitation attempts within hours. Maintainers call it a regression of CVE-2023-25158. There is still no CVE ID, no CVSS score and no vendor patch, and no confirmed compromises have been publicly described — only probing — which is why it appears here rather than in the table above. Inventory your deployments including H2-backed ones, restrict internet exposure and monitor database activity.
