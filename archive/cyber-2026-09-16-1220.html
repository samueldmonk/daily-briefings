Top Story

Forged admin tokens: WSO2 API Manager’s JWT bypass is under live attack

A critical flaw in WSO2 API Manager has come under active exploitation in the wild, according to findings from watchTowr reported by The Hacker News. Tracked as CVE-2026-5430 with a CVSS score of 9.8, the bug is an improper verification of a cryptographic signature: JWT authentication can be bypassed when a token is signed using an unsupported algorithm, which can result in account takeover.

watchTowr’s honeypot network captured JWT tokens arriving on 13 September 2026 with administrator privileges baked in — the attacker is not stealing a session, it is minting one.

Affected versions run across the supported line: 4.6.0, 4.5.0, 4.4.0, 4.3.0, 4.2.0 and 4.1.0. The vendor advisory is published as WSO2-2026-5328. Notably the CVE is not listed in the CISA KEV catalog, so there is no federal remediation clock attached to it — which is exactly the gap that makes it worth flagging above a KEV entry today.

Patch Priority

Today is the deadline: Starlette CVE-2026-48710 and LiteLLM CVE-2026-59822

Federal civilian agencies have until 16 September 2026 — today — to remediate the Kludex Starlette and BerriAI LiteLLM flaws added to the KEV catalog on 2 September. The Hacker News states the extended deadline explicitly: agencies have time until September 16, 2026, to address the Starlette and LiteLLM flaws. Starlette (CVSS 6.5) is an HTTP request/response smuggling issue that lets an attacker inject paths into the host portion of a request, prepending the real path and defeating authentication that depends on the reconstructed URL. LiteLLM (CVSS 8.8) is an improper-authentication flaw in the Model Context Protocol streamable HTTP endpoint that lets an unauthenticated attacker establish an authenticated MCP session with an arbitrary bearer token. Everyone else: if you run WSO2 API Manager on any 4.x release, treat CVE-2026-5430 as the higher-urgency item — it is being exploited today and has no federal clock behind it.

CenterPoint Energy confirms customer data stolen

The Houston-based utility, which serves about seven million customers across Indiana, Minnesota, Ohio and Texas, confirmed that an unauthorised third party stole customer data through one of its external-facing systems. A hacker using the alias 4d722e4d656f77 claims to have pulled 7.49 million customer records from an exposed API, with fields allegedly including names, phone numbers, billing addresses, account numbers and partial Social Security numbers. The hacker claims the API had no web application firewall, no rate limiting, no certificate checks and no authentication token.

WooCommerce plugin flaw used to plant PHP web shells

Threat actors are exploiting CVE-2026-27540 (CVSS 9.8) in WooCommerce Wholesale Lead Capture, a premium WordPress plugin with more than 6,000 active installs. An unauthenticated AJAX action, wwlc_file_upload_handler, checks file extensions against an allowlist supplied in a user-controlled file_settings parameter — so an attacker simply adds php to the permitted types and uploads a backdoor. Wordfence has blocked over 100,000 exploit attempts since June 2026, 99 of them in the past 24 hours. Fixed in version 2.0.3.2.
