Top Story

Nearly one in ten exposed LiteLLM gateways accepted the example key from the product’s own setup guide

Wiz Research scanned the internet-facing LiteLLM servers it could find on Shodan in February and reported the result this week: of 3,074 gateways, 294 accepted sk-1234 — the placeholder administrator credential printed in LiteLLM’s own Docker quick-start. In 191 of those 294 no master key was set at all, so they would have accepted anything; the rest had the documented value left in place. As of 9 September the setup guide still uses sk-1234, above a comment telling operators to replace it.

LiteLLM is an open-source AI gateway that sits between an organisation’s applications and the model providers it pays for, and its master key does two jobs at once: it is the admin credential and the switch that turns authentication on. Before version 1.82.0-stable, a gateway started without a master key treated every incoming request as an administrator. An admin on one of these servers can read every provider API key the gateway holds, see every prompt and reply passing through, and reach internal tools connected over the Model Context Protocol.

Wiz also showed the key reaching the cloud account underneath. LiteLLM lets an administrator create a pass-through endpoint that forwards requests to any URL, and the target is not checked against localhost, private ranges or cloud metadata addresses — so an admin can point a route at the instance metadata service and read back IAM credentials. Switching to IMDSv2 does not stop it, because LiteLLM documents that any header sent with an x-pass- prefix is forwarded with the prefix stripped. There is no CVE and no fix for that route: LiteLLM’s threat model treats administrators as trusted, and its security policy lists setup mistakes such as an unset master key as explicitly out of scope. Wiz reports no case of anyone using it against a real deployment.

The remedy needs no upgrade: change the master key to a long random value, checking first whether a separate salt key is set, because the rotation procedure differs and using the wrong one can leave stored credentials unreadable. Upgrading to 1.84.0 or later sits above the fixed version of every flaw in Wiz’s table.

Patch Priority

Patch Priority · Today

Patch Adobe Commerce / Magento today. CVE-2026-75650, tracked by researchers as StyleSmuggler, carries a CVSS score of 10.0 and allows unauthenticated remote code execution. It has been exploited in the wild since 4 September, with attackers reported deploying web shells and backdoors. CISA added it to the KEV catalog on 8 September and federal civilian agencies must remediate by Friday 11 September — 1 day left.

The same deadline covers CVE-2026-86218 in N-able N-central, a static code injection flaw also rated 10.0 that yields unauthenticated remote code execution; it is fixed in N-central 2026.3 Hotfix 4, released 5 September. The two Windows flaws added the same day run to 22 September instead.

Threat Actor Spotlight

Ransomware crews move onto WatchGuard’s Firebox firewalls

CISA has confirmed that ransomware gangs are now exploiting CVE-2025-14733, the critical WatchGuard Firebox flaw it first flagged as actively exploited in December. The bug is an out-of-bounds write that lets an unauthenticated attacker execute code remotely in low-complexity attacks, and it affects Fireware OS 11.x (including 11.12.4_Update1), 12.x (including 12.11.5) and 2025.1 through 2025.1.3.

WatchGuard says unpatched Fireboxes are exploitable only where IKEv2 VPN is configured — but warns that a device may still be compromised even after the vulnerable configuration is deleted, if a branch-office VPN to a static gateway peer remains configured. Shadowserver counted more than 115,000 unpatched Fireboxes exposed online in December; close to 9,000 are still unsecured nine months later, which is the population the ransomware crews are now working through.

Breaches & Incidents

NewAI infrastructure

Microsoft documents a live LiteLLM gateway compromise

In a case published in August, attackers ran commands inside a LiteLLM gateway process, read the container’s environment for the master key, the provider keys and the database connection string, then used that string to reach the PostgreSQL database and copy records from LiteLLM’s model and virtual-key tables. Microsoft assesses with high confidence that entry was through the exposed gateway, matching the CVE-2026-42271 / CVE-2026-48710 chain, and advises treating AI gateways as “Tier-0 secrets stores.”

NewRansomware

WatchGuard Firebox flaw folded into ransomware operations

CISA’s September update confirms ransomware gangs are leveraging CVE-2025-14733 for unauthenticated remote code execution against internet-facing Fireboxes. Nine months on from disclosure, Shadowserver still counts nearly 9,000 exposed unpatched devices.

NewVM escape

Broadcom patches a VMware Workstation and Fusion escape

VMSA-2026-0007, published 3 September, covers two desktop virtualisation flaws. CVE-2026-59346 is an integer overflow in the VMXNET3 virtual network adapter rated 9.3 by Broadcom: an attacker already holding local administrative rights inside a VM configured with a VMXNET3 adapter can execute code on the host. Workstation and Fusion 25H2 and 26H1 are affected; 26H1u1 remediates both. Both bugs were reported privately, not found through public exploitation.

CarriedCourt records

Thomson Reuters C-Track court software breach

Unauthorised access from 1 March to 29 June 2026, discovered 30 June, touching courts in 11 U.S. states, the U.S. Virgin Islands and Ontario. Exposed data includes SSNs, driver’s licences, dates of birth, medical and health-insurance data, and sealed records protecting domestic-violence victims and informants. Twelve months of Experian IdentityWorks is offered, with enrolment open to 31 December 2026.

CarriedSupply chain

JetBrains Cadence breached through unpatched TeamCity

Intruders exploited CVE-2026-63077, an insecure deserialisation flaw in TeamCity, between 8 and 24 August; the intrusion was discovered on 23 August and the server taken offline the next day. Multiple AWS IAM credentials, source code and secrets from a 2024 backup were taken, along with S3 objects in JetBrains AWS accounts.

CarriedMass exploitation

Langflow and Rails flaws drive credential-probing at scale

VulnCheck tracked exploitation of CVE-2026-0768 (9.8, arbitrary Python as root) and CVE-2026-66066, dubbed KindaRails2Shell (9.5, file read leaking secret_key_base, master key, database passwords and cloud credentials). Detections went from 50+ within hours on 30 August to 360; more than 7,100 exposed Rails instances were counted in early August. Probes query LANGFLOW_SUPERUSER, OPENAI_API*, AWS_ACCESS* and AWS_SECRET*.
