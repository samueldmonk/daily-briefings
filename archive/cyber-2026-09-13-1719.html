Top Story

The biggest Patch Tuesday on record shipped with two flaws already being exploited — and broke remote access on the way out

Microsoft fixed a record 974 CVEs in its September 2026 Patch Tuesday, shattering the previous record of 570 set in July 2026. Windows accounted for most of them at 723, followed by Office at 111, with SQL Server, Exchange Server, SharePoint Server, Azure and developer tools also covered. Microsoft singled out two flaws it had already detected being exploited before the release: CVE-2026-85880, a privilege-escalation bug in Windows Advanced Local Procedure Call rated CVSS 7.8 — local access required, no additional user interaction, affecting Windows 10 and Windows Server 2012 through Server 2022 — and CVE-2026-81963, a second privilege-escalation flaw in the Windows Update Stack. Security Affairs counts 20 wormable bugs in the set. Microsoft had warned customers in July to expect a surge in security updates as a result of its use of agentic AI tools to discover zero-day vulnerabilities.

The same cycle is now causing outages of its own. KB5124008, the 8 September cumulative update for Windows 11 24H2 (build 26100.9445) and 25H2 (26200.9445), is knocking enterprise clients off certificate-based Always On VPN; separately, KB5122876 / KB5122882 / KB5122871 for Windows Server 2019/2022/2025 break Remote Desktop Services after a few hours of normal operation. Neither is a vulnerability — both are availability defects with no CVE and no attacker — but the only confirmed recovery for each is removing the update, which also removes the month’s security fixes.

Naming note: the CISA alert listing read this run describes CVE-2026-81963 as a Windows link following flaw and CVE-2026-85880 as a heap-based buffer overflow, while the vendor-side reporting read this run calls them ALPC and Windows Update Stack privilege escalation. Both namings are printed; neither has been merged into the other.

ShinyHunters

The group’s claim of patient-data theft at McKesson now has a company answer: McKesson confirmed a cybersecurity incident discovered 25 August 2026, saying an unauthorised party reached certain third-party applications and exfiltrated data associated with a subset of customers. ShinyHunters is also one of the clusters Microsoft named in its 9 September write-up of passkey-themed help-desk social engineering, alongside Helix, Storm-3121 and Storm-3032 — a pattern of reaching identity and cloud data through people and third parties rather than through malware.

Breaches & Incidents

Newavailability

KB5124008 breaks certificate-based Always On VPN

Administrators report that Always On VPN tunnels working immediately before the 8 September cumulative update stop connecting afterwards, and recover as soon as the update is removed and the device is rebooted. The first detailed account appeared on Microsoft Q&A on 9 September, from an admin running Windows 11 24H2 and 25H2 clients with certificate-based authentication, RRAS plus Network Policy Server on Server 2019, and an Intune-deployed VPN profile. Guidance so far is to hold the rollout in WSUS and Intune; uninstalling and rebooting is the only confirmed recovery.

Newconfirmed

McKesson confirms incident after ShinyHunters claim

The healthcare distributor confirmed a cybersecurity incident discovered 25 August 2026: unauthorised access to certain third-party applications, and exfiltration of data associated with a subset of customers. The confirmation followed ShinyHunters’ public claim of patient-data theft.

Two open discrepancies, printed rather than resolved. (1) Earlier editions of this page recorded a 9 September alert adding four flaws, listed as 20079 / 19490 / 2025-25249 / 87491. The alert listing returned this run instead gives 8 September for the four-CVE alert, and its four are Adobe, two Microsoft entries and N-able. (2) CVE-2026-87491 appears in no September alert enumerated this run; the Chromium V8 entry that does appear is CVE-2026-85046, added 4 September. Both prior claims are therefore left unsupported rather than restated. Separately, the directive cited by this run’s KEV material is BOD 26-04, not BOD 22-01 — so no deadline anywhere on this page is calculated from an add date; only dates stated at source are printed.
