Top Story

Actively exploited — now a KEV entry

CISA adds the Chrome V8 zero-day to KEV, one day after Google shipped the fix

CISA’s September 4 alert added a single vulnerability to the Known Exploited Vulnerabilities catalog: CVE-2026-85046, a type-confusion bug in V8, the JavaScript and WebAssembly engine behind Chrome. Google states plainly that “an exploit for CVE-2026-85046 exists in the wild,” and the flaw lets a remote attacker execute arbitrary code inside Chrome’s sandbox by way of a crafted HTML page. It carries a CVSS score of 8.8.

The fix shipped in Chrome 152.0.7977.82/.83 for Windows and macOS and 152.0.7977.82 for Linux, in a Thursday advisory; Help Net Security counts 12 vulnerabilities fixed in that release. It was reported by researcher Salvatore Gulizia (Serotav) on August 4, 2026, for a $1,000 bounty — a small reward for a bug that reached in-the-wild exploitation. In his own write-up Gulizia describes the root cause as a compiler bug in which an array holding PACKED_ELEMENTS receives the map PACKED_SMI_ELEMENTS, which can be turned into arbitrary read/write on the JavaScript heap.

This is the sixth actively exploited Chrome zero-day of 2026. New The five before it, named this run for the first time: CVE-2026-2441, CVE-2026-3909, CVE-2026-3910, CVE-2026-5281 and CVE-2026-11645. Google has not named the threat actors, the targets or the campaigns while the update is still rolling out.

Patch Priority

Do this first

Update Chrome to 152.0.7977.82 or later on every desktop you manage. This is the one item on the page that is both confirmed exploited in the wild by the vendor and confirmed listed in CISA KEV as of September 4. The patch is available; the exploit is live; the only variable is how quickly the rollout reaches your fleet, and Google notes it rolls out “over the coming days and weeks” — so push it rather than waiting for it.

A deadline this desk published yesterday has been withdrawn. The previous edition stated a September 18 KEV due date for CVE-2026-85046. That date could not be re-confirmed against any source fetched this run, so it is not asserted here. Separately, this run established that federal remediation timing now runs under BOD 26-04, “Prioritizing Security Updates Based on Risk,” a risk-based successor under which vulnerabilities meeting all four high-risk criteria must be mitigated in no more than 3 days — not the uniform three-week window this desk had assumed. No specific due date for this CVE is claimed.

Threat Actor Spotlight

Storm — ransomware, first observed August 2026

Storm is a ransomware operation first observed in August 2026, credited with roughly 44–48 victims across healthcare, financial services, manufacturing, technology, transportation and government — overwhelmingly U.S. organisations. This desk publishes the range rather than a single figure inside it, because the reporting gives a range. Its most recent listing of note is Star Aviation Inc. of Goshen, Kentucky, a maker of engine wire harnesses and wire interconnect systems and an FAA PMA parts supplier to Boeing and Airbus programmes, posted to Storm’s leak site on September 2. That remains an attacker claim: no record count, no data volume and no ransom figure has been reported, and the company has not confirmed it.

A caution this desk learned the hard way: a search for a September 4 “Boeing and Airbus supplier” breach returns a Qilin/LISI Group story whose published_time is 2026-03-02 — six months old, different gang, different country, different company. Check the publication timestamp on anything a search summary dates to today.

  • August 31 — two additions, now named New: CVE-2026-81578 (PaperCut, missing authentication for a critical function) and CVE-2026-82078 (PaperCut, unsafe reflection). Prior editions could confirm only that this batch existed.
  • August 11 — three additions, now named New: CVE-2026-20349 (Cisco Secure Firewall ASA/FTD, heap inspection), CVE-2026-68820 (Microsoft Windows, use-after-free) and CVE-2026-72898 (Metabase, SQL injection).
  • The deadline model itself has changed New: federal remediation now runs under BOD 26-04, “Prioritizing Security Updates Based on Risk.” Rather than a uniform window, it requires FCEB agencies to prioritise KEV-listed flaws on publicly exposed assets that grant total control post-exploitation, with the highest-risk category mitigated in no more than 3 days. Per-CVE due dates therefore vary by risk rather than running to one uniform window. This page deliberately does not cite the differing due dates earlier editions carried for the September 2 batch as evidence of that: those dates were not re-confirmed this run, and it would be circular to lean on withdrawn figures. No individual due date is claimed for any CVE above.
